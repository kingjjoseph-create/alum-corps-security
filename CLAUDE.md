# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

Marketing website for **Alum Corps Security LLC**, a Florida-licensed security agency. Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4. Next.js 16 differs from older versions; check `node_modules/next/dist/docs/` before using an API you haven't verified (for example, `next/image` `priority` is deprecated, so use `loading="eager"`).

## Commands

```bash
npm run dev            # dev server at http://localhost:3000
npm run build          # production build (also type-checks)
npm start              # serve the production build
npm run lint           # ESLint (next/core-web-vitals + typescript); keep at 0 warnings
npx tsc --noEmit       # type-check only
```

There is no test suite. Before committing, run `npm run lint`, `npx tsc --noEmit` and `npm run build`. For UI changes, also check the page at 375, 768, 1024, 1440, 1920 and 2560px wide. Chromium is at `/opt/pw-browsers/chromium` for Playwright; launch it with `--no-proxy-server` to reach localhost.

## Architecture

**Single source of truth: `lib/site.ts`.** Company name, legal name, phone (display and `tel:`/E.164 forms), email, fax, license (number, class, issuer, verification URL), service areas, optional address (hidden while `null`), navigation, services, capabilities and leadership all live here. Never hard-code these values in components; read them from `site.*`. Page copy lives in `lib/commercial.ts`, `lib/residential.ts`, `lib/event.ts`, `lib/services-detail.ts` and `lib/careers.ts`. Each item carries its own `icon` component, so render it as `<item.icon />` rather than adding lookup maps.

**Server first.** Pages and sections are Server Components. Only these are client components: `Header`, the four forms (`QuoteForm`, `CoverageForm`, `ContactForm`, `CareersForm`) and `RevealObserver`. Keep it that way. `Reveal` is server-rendered markup (`data-reveal`), and a single `RevealObserver` mounted in `app/layout.tsx` animates every reveal element. Don't give `Reveal` its own effect. The layout's inline script adds a `js` class to `<html>`, so content stays visible without JavaScript.

**Metadata and SEO.** Next.js merges metadata *shallowly*, so a page that sets `openGraph` replaces the layout's entirely. Every interior page must use `export const metadata = pageMetadata({ title, description, path })` from `lib/seo.ts`; it emits canonical, Open Graph, Twitter and the share image. The share image is generated by `app/opengraph-image.tsx`. Structured data always goes through `<JsonLd data={…} />`, which escapes `<`. The layout emits the organization (`LocalBusiness`, `@id` `${site.url}/#organization`). Service pages emit a `Service` whose `provider` references that `@id`. `PageHero` automatically emits the `BreadcrumbList` from its `breadcrumbs` prop. Add every new route to `app/sitemap.ts`.

**Forms pipeline.** Client form → server action in `app/actions/` → `lib/form-validation.ts` (`field`, `oneOf`, `isEmail`, `isPhone`, `isBot`, shared `messages`) → `lib/deliver-lead.ts`. That last file is the **only** place leads leave the app. It emails via Resend when `RESEND_API_KEY` is set (optional `QUOTE_TO_EMAIL`, `QUOTE_FROM_EMAIL`). Without a key, it logs to the console in dev and in production tells visitors to call or email instead. To connect a CRM, change only `deliver-lead.ts`.
- Action state shape: `{ status, message?, errors?, values? }`. Values are echoed back on error, and the `<form>` is keyed on them so fields remount with what the visitor typed (React 19 resets forms after an action).
- Shared pieces live in `components/FormField.tsx`: `Field`, `inputClass`, `ChoiceGroup` (radio/checkbox buttons), `FormSection`, `Honeypot` (field name `company_website`), `FormSuccess`, `invalidProps`, and `useFocusFirstError` (scrolls to the first invalid field after a failed submit).
- **Careers form is design-only on purpose.** `applicationsEnabled = false` in `lib/careers.ts`, there is no server action, and native submit is always prevented. It collects license numbers and resumes, so don't add an endpoint until a secure backend exists (see README, "Enabling online applications").

**Quote calls to action.** Site-wide "Get a Quote" links use `site.quoteHref` (`/request-a-quote`, the full coverage form). The homepage and service pages also embed `QuoteSection` (the short form) at `#request-quote`, and their hero buttons link to that anchor. "Speak With Our Team" links to `/contact`.

**Header behavior (don't regress).** The dropdown opens on hover only for `pointerType === "mouse"`; touch tablets use the toggle's click, and plain `onMouseEnter` breaks iPad. While the mobile menu is open, `#main`, `footer` and the skip link are `inert`. Escape returns focus to the control that opened the menu. The menu also closes when the viewport reaches `lg`.

**Large-display scaling.** `html` font-size is 112.5% at ≥1920px and 125% at ≥2400px, so size everything in rem/Tailwind units, never px. Breakpoints are unaffected. `<Logo width={…}>` derives `sizes` from its base width to match this scaling.

## Logo rules

- The only logo is `public/images/alum-corps-logo.jpg`, the owner-supplied embroidered patch. **Never redraw, recolor, crop, add effects to, change the opacity of, or stretch it.** Always render it through `<Logo>`, which keeps its 1:1 ratio, and size it with a height class (`h-16` to `h-20` in the header, `h-28` in the footer).
- The artwork includes the "ALUM CORPS SECURITY" wordmark, so don't set text beside it.
- The logo's black background matches `--color-ink` (`#030303`). Keep it on ink backgrounds; on a lighter or gradient background its square edge shows.
- `app/icon.png` and `app/apple-icon.png` are resized copies; regenerate them from the original if the logo ever changes.

## Color

All colors come from the tokens in `app/globals.css` (`@theme`). Don't put raw hex or `rgb()` values in class names.

| Token | Value | Use |
|---|---|---|
| `ink` | `#030303` | Page background (matches the logo's background) |
| `coal` | `#0e0e0e` | Alternate section background |
| `graphite` | `#161616` | Cards and panels (usually `bg-gradient-to-b from-graphite to-coal`) |
| `gold` | `#dead2f` | Accent; sampled from the logo's gold |
| `gold-light` / `gold-dark` | `#f2cc66` / `#a87f1a` | Gradients (buttons, `text-gold-gradient`) |
| `mist` | `#a3a3a3` | Secondary text |

- **White text opacity:** use only `text-white/85`, `/75`, `/60` or `/50`.
- **Borders:** `border-white/10` for neutral hairlines, `border-gold/15` to `/40` for accents.
- **Glows:** use the shadow tokens `shadow-glow`, `shadow-glow-lg`, `shadow-glow-xl`, `shadow-card` and `shadow-panel`.
- **Errors:** `text-red-300` with a `border-red-400` invalid state.
- **Contrast:** everything must pass WCAG AA. Avoid low-opacity text, and mark decorative numerals `aria-hidden`.

## Typography

- **Display:** Cormorant Garamond, **weight 600 only, normal and italic** (`font-display font-semibold`), for headings, section titles and large numerals. It's loaded in `app/layout.tsx`; add any new weight or style there first, or browsers will fake it. Lining numerals are forced globally.
- **Everything else:** Inter (`font-sans`).
- **Headline pattern:** a white serif headline with the key phrase in a gold italic span, e.g. `Request security <span className="text-gold-gradient italic">coverage.</span>`. `.text-gold-gradient` already pads the italic overhang so wrapped glyphs aren't clipped.
- **Labels:**
  - `.eyebrow` goes above section headings (gold caps with a leading rule).
  - `.label-caps` is for small gold caps labels on cards and contact blocks.
  - Letter-spacing scale: `0.3em` labels, `0.2em`–`0.25em` meta, `0.16em`–`0.18em` buttons, `0.1em`–`0.14em` tight phone variants. `0.4em`/`0.55em` are reserved for the homepage brand line.
- **Minimum sizes:** body text at least 12px, form inputs at least 16px (so iOS doesn't zoom in on focus).

## Layout and component standards

- **Page skeleton:** interior pages start with `PageHero` (eyebrow, title, intro, breadcrumbs, optional `aside`, `showCtas={false}` for form pages), then sections, then usually `QuoteSection` with `defaultService`.
- **Sections:** `py-28 sm:py-36`, container `mx-auto max-w-7xl px-6 lg:px-8`. Alternate `ink` and `coal` backgrounds, separated by `border-y border-gold/15`. Use `SectionHeading` for every section heading.
- **Grids:** hairline grids use `gap-px overflow-hidden border border-white/10 bg-white/10` with cells in `bg-ink`/`bg-coal`. Three-column layouts switch on at `lg` (not `md`), because 768px is too narrow.
- **Decoration** comes from `components/Decor.tsx`: `CornerAccents` (gold L-brackets), `HoverRule` (gold line on card hover) and `FormPanel` (the framed panel around every form). Reuse these rather than copying the markup.
- **Buttons:** use `ButtonLink` (`primary` gold gradient, `outline`, `ghost`). Labels stay on one line from `sm` up, and button rows use `sm:flex-row sm:flex-wrap`.
- **Touch targets:** standalone links (phone, email, footer, breadcrumbs) get `min-h-11 lg:min-h-0`, i.e. 44px below desktop.
- **Motion:**
  - Page `<h1>`s use `animate-rise`, which moves without changing opacity, so the main content isn't hidden from Largest Contentful Paint timing.
  - Other hero items use `animate-fade-up`; content below the fold uses `<Reveal>`.
  - Everything respects `prefers-reduced-motion`.
  - Avoid paint-heavy effects (SVG noise filters, `mix-blend-mode`, animated blurs without `will-change`); a grain overlay was removed for this reason.
- **Quality bar** (current state; keep it):
  - Lighthouse mobile ≥94 and desktop 99, with Accessibility, Best Practices and SEO at 100.
  - axe WCAG 2.2 AA: 0 violations.
  - No horizontal scroll from 320px to 2560px.
